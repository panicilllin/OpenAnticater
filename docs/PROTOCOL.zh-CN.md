# ANTICATER MINI 改键协议

适用于单旋钮款 ANTICATER MINI（蓝牙名 `ANTICATER_MINI`）。来源：原厂 macOS App
`ANTICATER.app`（2025-08-20 签名版，x86_64、Qt 5.12、hidapi）的反汇编（符号未剥离），
以及用只读命令对实物的查询。标注「已实测」的内容在实物上验证过。

## 设备与接口

| 连接方式 | VID:PID | 能否改键 |
|---|---|---|
| USB 线直连 | `514C:8850` | 能。接口 0 是厂商自定义通道（用途页 `0xFF00`，收发都是报告 ID 3 + 64 字节）；接口 1 是普通键盘/鼠标/多媒体 |
| 蓝牙 | `05AC:022C`（冒充苹果键盘） | 不能 |
| 2.4G 接收器 | `514C:4155` | 不能 |

原厂 App 认识的 PID：VID `1189` 或 `514C` 下的 `8842 8840 8830 8831 8832 8833 8850 8851`。

下文报文都省略开头的报告 ID `03`；设备的回复里会带上它。

## 查询形态 `FB FB FB`（已实测）

回复 `03 FB <键数> <旋钮数> <版本> …`。本机回复 `00 01 00`：0 个按键、1 个旋钮、版本 0。
版本 ≥ 10 的新固件走另一套带 65 字节记录、支持单键 RGB 的流程，本 App 没有实现。

## 读取一层 `FA 0F 03 <层>`（已实测）

层号 1–3。设备逐条回复 24 条记录（键位 1–24，顺序不固定）：

```
03 FA <键位> <层> <类型> 00 00 00 00 00 <数量> <数据…>
```

## 写入一个键位 `FD <键位> <层> <类型> 00×5 <数量> <数据…>`

格式与读取回复一致，只是命令字节 `FA` 换成 `FD`。老固件只用前 50 字节，其余填 0。
原厂 App 每写完一层发一次提交 `FD FE FF`，然后等 1 秒。

### 键位

原厂 App 的「0 键 + 1 旋钮」布局（`Set_Keyboard_0add1`）把旋钮的 5 个动作放在：

| 动作 | 键位 |
|---|---|
| 左转 | 16 |
| 按下 | 17 |
| 右转 | 18 |
| 按住左转 | 19 |
| 按住右转 | 21 |

键位 20 不使用；1–15 是给多键款用的。

已实测：把第 1 层键位 16 临时写成「音量 +」后，物理左转会调音量，说明键位 16 就是左转，
且写入 + 提交后立即生效、不需要重新插拔。

### 类型与数据

| 类型 | 含义 | 数据 |
|---|---|---|
| `01` | 按键 | 数量 n（1–18），然后 n 组 `修饰键, HID 键码`；n > 1 时依次输出 |
| `02` | 多媒体 | 数量 1，然后 Consumer 用途码（小端 16 位），如 `E9 00` 音量加 |
| `03` | 鼠标 | 数量 1，然后 `修饰键, 按键, X, Y, 滚轮`；按键 1 左 / 2 右 / 4 中；滚轮 ±1 |
| `05` | 延时 | 未实现 |

修饰键位图：`01` Control、`02` Shift、`04` Option、`08` Command。

## 灯效 `FE B0 <层> 08 00×5 01 00 <灯效字节>`

写在 0 号键位，和键位记录一起在提交前发送（已实测生效）。

原厂 App 把灯效字节解释为「颜色 << 4 | 模式」（颜色 1–7：红橙黄绿青蓝紫；模式 0–5：关闭、顺时针、逆时针、交替、跳跃、闪烁，
没选颜色时补颜色 5）。但**这台旋钮（固件版本 0）只看低 4 位，高 4 位写什么都没有效果**。实物观察：

| 低 4 位 | 实际效果 |
|---|---|
| 0 | 无光 |
| 1 | 白光 |
| 2 | 绿光 |
| 3 | 跑马灯 |
| 4 | 红、绿、蓝轮换 |
| 5 | 快速跑马灯（出厂默认） |
| 6 | 与 5 相近，原厂不提供，本 App 不开放 |

测过的完整字节：`00`、`10` 无光；`01`、`11`、`31`、`51` 白光；`13` 跑马灯；`15` 快速跑马灯。

老固件对读取灯效（`FA B0 …`）没有回复，所以灯效读不回来。

## 用哪一层

3 层都能读写。实测时旋钮的实际行为和第 1 层的内容一致，第 2、3 层是厂商默认值（音量、播放 / 暂停、切歌），
说明固件当前用第 1 层。单旋钮款没有切换层的按键，为保险起见本 App 写入时 3 层写同样的内容。
